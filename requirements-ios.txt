# Only for the "ios" source (USB iPhone / iPad Safari). Not needed otherwise.
#
# Floor of 10.2.0 (2026-07-28, PR #1803), which rewrote the CDP bridge and fixed the
# two crashes green_light used to patch around: Target.targetCreated popping
# isProvisional without a default, and evaluate_and_result indexing a missing
# "result". Either one killed CdpTarget's receive loop -- silently, since nothing
# awaits it -- and the capture then blamed the phone for going away. Below 10.2 that
# happens on current iOS, so this is a real floor, not a preference.
#
# No upper bound. gl_ios.py does drive internals (starts the bridge itself because the
# `webinspector cdp` CLI cannot run, rebuilds webSocketDebuggerUrl because the bridge
# hardcodes port 9222, restores the console source location the bridge drops), so an
# upgrade can still shift behaviour. But pinning below 10.2 meant carrying our own
# copies of bugs upstream had already fixed, which is the worse trade: those patches
# failed by losing the whole capture, whereas the remaining one fails by losing a
# file:line prefix. gl_ios reads both console shapes (Log.entryAdded and, from 10.2,
# Runtime.consoleAPICalled), so it spans the boundary either way.
#
# Known-good anchor, for bisecting if a later release breaks capture. Upstream ships
# fast (seven releases over 2026-08-26..29), and the pump guard keeps a bad one from
# failing silently -- but only a recorded combination says how far back to go.
#   pymobiledevice3 11.2.1 / iPhone12,8 iOS 26.5.2 / Windows  (2026-08-29)
#   verified: --check 3/3, capture with file:line, no false disconnect
pymobiledevice3>=10.2
